# T70 网页端批量导入上游 Key（已批准，已完成）

## 1. 问题

管理界面的「上游 Key」页只能一次加一把。几十把 Key 要么逐个粘贴，要么改用命令行 `gateway keys import`；后者需要终端、管理令牌和环境变量，不是每个使用者都方便。

另外，现有的 `POST /admin/api/keys` 每加一把都会从库里重新加载、解密**全部** Key 并替换调度器的 Key 表（ADM-14）。如果网页端循环调用它，导入 N 把就要做 N 次全量重载。

## 2. 目标

- 在 Key 页增加「批量导入」：可以粘贴文本，也可以选择本地文件，支持三种格式。导入前先预览统计，确认后才提交。导入完成后显示结果。
- 新增一个服务端批量接口：一次请求写入多把 Key，**只做一次**重载。
- 和命令行导入保持同样的语义：过期的默认跳过；重复的按 Key 指纹判定；可选择更新已有 Key 的过期时间和标签。

不在本卡范围内：命令行改用新接口（以后可以做，行为不变）；删除 Key；导出 Key。

## 3. 决策（建议）

| # | 问题 | 建议 | 备选 |
|:-:|:--|:--|:--|
| 1 | 文件在哪里解析 | **在浏览器里解析**，服务端只接收结构化的条目（密钥、过期时间、标签）。文件里的邮箱、密码等其他字段不会发给网关 | 上传原文件、在服务端解析：服务端要实现三种格式，账号文件的全部内容也会经过网络 |
| 2 | 服务端接口 | 新增 `POST /admin/api/keys/import`，每条单独校验、单独写入（不是全部成功或全部失败），最后统一重载一次 | 让网页循环调用现有接口：N 次全量重载，部分失败也不好汇总 |
| 3 | 支持的格式 | ① 每行一把 Key；② JSONL，可选择密钥字段、过期字段、标签字段，以及「字段 = 值」过滤（例如 `status=ok`）；③ 带表头的 CSV，可选择对应列 | 只支持每行一把：账号文件需要先手工转换 |
| 4 | 过期时间 | 和命令行接受同样的格式（RFC 3339、Unix 秒、`YYYY-MM-DD HH:MM:SS`、`YYYY-MM-DD`），可选时区，默认浏览器所在时区。在浏览器里换算成 RFC 3339 再提交；已过期的默认跳过，可以勾选「也导入已过期的」 | — |
| 5 | 命名 | 页面上填名称前缀（默认是池名），由**服务端**分配 `<前缀>-NNN`，编号接在该池同前缀现有的最大编号之后。重复导入时名字不会撞 | 浏览器按当前列表计数：并发导入时可能撞名 |
| 6 | 重复的 Key | 默认计为「重复」并返回已有 Key 的 ID；勾选「更新已有 Key 的过期时间和标签」时改为更新 | — |
| 7 | 规模上限 | 单次请求最多 1000 条，请求体仍受现有的 1 MiB 限制；超过 1000 条时，网页按每批 500 条依次提交，进度条显示进度 | — |
| 8 | 并发 | 整批都在管理面现有的写操作串行锁（`serial`）内执行 | — |

## 4. 规则（拟写入 spec/09）

| 编号 | 规则 |
|:--|:--|
| ADM-23 | `POST /admin/api/keys/import`。<br>请求体：`{"pool", "name_prefix"?, "weight"?, "max_in_flight"?, "update_existing"?: bool, "items": [{"secret", "expires_at"?, "label"?}]}`。<br>1 ≤ `items` ≤ 1000，否则返回 400。`pool`、`weight`、`max_in_flight`、`label`、`expires_at`、`secret` 的校验与 ADM-13 和 T62 相同。<br>每条单独处理，结果为 `created`、`updated`、`duplicate`、`invalid` 之一。<br>全部处理完后执行一次 `LoadKeys` 和 `SetKeys`，只有新增或更新了至少一条时才执行。<br>响应 200：`{"created", "updated", "duplicate", "invalid", "results": [{"index", "status", "key_id"?, "name"?, "secret_hint"?, "error"?}]}`。 |
| ADM-24 | 批量导入的响应、错误信息、日志与审计记录都**不包含**密钥明文：只有序号、`secret_hint`（`obs.MaskSecret`）与数量。审计记录一条，内容为池名与各项数量 |
| UI-34 | Key 页增加「批量导入」按钮，打开对话框，分三步：<br>① 选择池，粘贴文本或选择文件（读取上限 8 MiB）；<br>② 选择格式与字段映射（JSONL 和 CSV 的字段下拉框取自前几行），设置过期字段、时区、标签、名称前缀，以及「跳过已过期 / 更新已有」两个选项；预览只显示统计（可导入、已过期、无效、被过滤），不显示任何密钥；<br>③ 提交并显示结果：各项数量，以及无效与失败行的行号和原因。<br>对话框关闭或导入完成后，清空文本框和内存中的条目 |

## 5. 测试

- `internal/admin`：
  - 正常导入；
  - 单条无效和重复混合；
  - `update_existing` 更新过期时间与标签；
  - 名称编号接续；
  - 0 条或 1001 条返回 400；
  - 未配置的池返回 400；
  - 整批只重载一次（用计数的 Scheduler 替身）；
  - 响应与日志中没有密钥明文。
- UI 测试（`ui_test.go` 的静态检查）：页面有导入入口，提交的是新接口，不在页面上渲染 `secret`。
- 端到端：用网页实际使用的请求格式导入 3 种格式的样例（测试数据现场生成），调度器能立即用上新 Key。
- 实测：在浏览器面板里用本地生成的假 Key 文件导入，确认结果和统计。真实账号文件只能由你在浏览器里自己选择，我不读取文件内容。

## 6. 实现中的补充

- 结果状态多了一种 `failed`：存储出错时（不是请求本身的问题）计入，不中断整批。
- 对话框增加「密钥前缀」（对应命令行的 `--secret-prefix`，例如 rest 池的 `bearer:`）。
- 每批除了不超过 500 条，请求体也控制在 900 KiB 以内；导入请求的超时为 120 秒（`api()` 增加可选的 `opts.timeout`，其他请求仍是 15 秒，UI-19）。
- `update_existing` 只写条目中**出现的**字段：选择了过期字段时每条都会带 `expires_at`（空字符串 = 清除），设置了标签或标签字段时才带 `label`，与命令行 `--update` 一致。

- 样式表增加 `[hidden] { display: none !important; }`：实测发现带 `.stack` 等类的元素设置 `hidden` 后仍然显示（类选择器的 `display` 优先）。
- 导入结果中同时显示「提交前已在浏览器中跳过」的数量（已过期、无效、被过滤），预览清空后仍能看到。

### 6.1 实测结果（2026-11-13，浏览器面板，全部为现场生成的假 Key）

1. 粘贴 4 行（含注释与一行带空格的），密钥前缀 `bearer:`、标签 `web-paste`：预览「可导入 3 · 无效 1」，导入后新增 3，名称 `demo-openai-001..003`，提示为 `bear****1111` 等，文本框已清空。
2. 1200 行 JSONL 文件（字段过滤 `status = ok`、过期字段、标签字段、时区 +08:00）：预览「可导入 1,056 · 已过期 24 · 无效 1 · 被过滤 120」与预期一致；分 3 批（500、500、56）提交，新增 1056，名称 `demo-rest-001..1056`，`12:00 +08:00` 存为 `04:00Z`，标签按字段分布正确。
3. 含 2 把已有 Key、1 把新 Key、1 行已过期的文件，勾选「更新已有 Key」：更新 2（过期时间被改写或清除、标签改写），新增 1（编号接续为 `-004`），未出现在文件中的 Key 不变；Unix 秒正确换算；过期字段自动选中。
4. 网关日志每批一条 `admin: upstream keys imported`，只有池名与数量；日志中没有任何测试密钥。
