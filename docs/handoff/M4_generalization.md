# M4 通用化（总览）

- **状态**：2026-11-13 用户同意把 M4 从「Key 池运营」扩大为「通用化」；各卡规格逐张审批。T62 已完成。
- **约束**：不改内核（`internal/core`）与契约（`internal/protocol`）的导出 API，不改分层规则与 adaptertest 套件，不加依赖。设计中如果发现必须改内核，停下来报告，不绕过。

## 1. 出发点

问题不是「MinerU 还缺什么」，而是「**接第 10 个、第 50 个 API 时，框架在哪里卡住**」。回看 M3 的实际接入（Bivia、Tavily、MinerU、Gemini）与 2026-11-12 导入 270 把真实 Key 的实测，卡点有四类：

| # | 卡点 | 证据 | 主线 |
|:-:|:--|:--|:--|
| 1 | 稍微复杂一点的 API 就要写 Go 适配器 | MinerU 占了 T59、T60 两张卡；用通用 REST 转发接 MinerU 时，轮询没有固定到提交任务的 Key，返回 -60012 | 声明式 API 能力（T66、T67） |
| 2 | 运行时状态只在内存里 | 重启后冷却中的 Key 被重新调度、各失败一次；异步任务的固定记录丢失，查询返回 404 | 状态持久化（T68） |
| 3 | Key 的生命周期靠人工 | 过期账号要手工过滤（T62 已解决）；周期额度要先失败一次才冷却；新账号要手工导入 | Key 池运营（T63 ~ T65） |
| 4 | AI 拿不到本地文件 | MCP 工具只收 URL | 文件中转（T69） |

这些都不是某个 API 独有的：业务错误码写在 HTTP 200 的响应体里、异步任务、预签名上传、用量写在响应里、额度定时重置，在国内外大量 API 中反复出现。

## 2. 卡片与依赖

```
T61 打底（建议最先做）
T66 声明式 A ──► T67 声明式 B ──► T69 文件中转
      │
      ├──────────────┐
T68 状态持久化 ──────┴──► T63 按额度调度 ──► T65 Key 视图
T62（DONE）──────────────► T64 补充与告警
```

| 卡 | 交付 | 检验标准 |
|:--|:--|:--|
| T61 | Linux `-race` 全量测试；24 小时稳定性基线（内存、goroutine、延迟）；`gateway backup` / `restore` | 有竞态检测报告与基线数据 |
| T66 | 服务配置中声明：业务错误映射（状态码与 JSON 字段 → 结果分类，含「冷却到某个时刻」）、用量提取（响应或请求的 JSON 字段 → 计量单位）、异步任务（创建时记录任务 ID，查询固定到同一 Key） | 只用配置接入 MinerU 的异步任务与 Tavily 搜索，用真实 Key 实测，计费与专用适配器一致 |
| T67 | 同步等待（提交 → 轮询 → 取结果，一次请求完成）与预签名上传 | 只用配置重写 MinerU 的 `/v1/parse` 与本地文件上传，通过同样的实测 |
| T68 | 冷却截止时间、任务固定记录、（T63 之后）周期用量由控制面定期写入数据库，启动时恢复 | 重启前冷却的 Key 重启后仍在冷却；重启前创建的异步任务重启后仍可查询 |
| T63 | 池级额度声明；每 Key 周期用量；用满主动冷却到重置时刻；`drain` / `spread` 两种策略 | Key 用满后不再先失败一次 |
| T64 | `gateway keys sync`（JSONL、纯文本、CSV）；池可用 Key 或剩余额度低于阈值时告警；快过期提醒 | 注册程序产出的新账号自动进池 |
| T65 | 每 Key 与每池的用量、剩余额度、失败率、过期时间、预计耗尽时间（Web UI、管理面 MCP） | 可以问 AI「这个池这个月还够用吗」 |
| T69 | 上传一次得到文件 ID，任何工具用 ID 引用；大小、数量、保存时间有上限 | AI 能把本机文件交给 MinerU 解析 |

**为什么 T63 等 T66、T68**：额度重置时刻、用量来自哪个字段，都是 API 的描述，属于 T66；周期用量必须能跨重启，属于 T68。先做 T63 会在这两处各做一遍。

## 3. 边界与取舍

- **声明式描述只覆盖已经在真实 API 中出现过的模式**。不做条件分支、循环、脚本、自定义函数；表达不了的 API 照样写 Go 适配器。防止 YAML 变成一门编程语言。
- **专用适配器保留**：`tavily`、`mineru` 继续可用。声明式能力稳定之后，再评估是否把它们改为配置（届时单独立卡）。
- **不在 M4 范围**：编程 Agent 兼容（WebSocket Responses 等，需要先收集失败样本）；多实例、PostgreSQL、对外服务（单机够用之前不做）；主动探测上游余额（各家没有统一接口；先靠网关自己的计量推算）。
